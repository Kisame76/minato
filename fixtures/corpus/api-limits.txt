# The API types that stay missing, and why (tools/api-coverage.py --limits): `<qualified type> <group> <reason id>`.
# Only what cannot exist on an iPhone or is a stated non-goal; a type an app can reasonably call is a task, not here.
# The reasons are repeated in docs/COMPATIBILITY.md, "Limits that stay".

# reason apache-http: the legacy Apache HTTP client's classes, removed from Android's API in 6.0: not a goal
# reason carrier-network: the virtual carrier network (VCN): a carrier- and system-only API
# reason device-admin: device administration, enterprise and recovery: only a device owner or the system uses it
# reason gnss-raw: raw GNSS measurements and location setting injection: iOS gives apps no raw satellite data
# reason print-hardware: the print framework's services and jobs: iOS prints through AirPrint, not through these classes
# reason secure-hardware: trusted UI, the secure element (OMAPI) and identity credentials: hardware iOS gives no app
# reason system-service: a base class an app implements for the Android system to bind (accessibility, IME, dream, ...)
# reason telephony: an iPhone gives an app no telephony stack: calls, SMS, SIM, eSIM, SIP, RTP, carrier and IMS services
# reason test-only: instrumentation and test automation: runs only under an instrumentation
# reason tv-platform: Android TV platform services and views (TV input, ads, interactive apps): an iPhone is no TV
# reason wifi-hardware: Wi-Fi Aware, RTT, Passpoint, Wi-Fi Direct discovery, Easy Connect, Wi-Fi setup: no iOS API
