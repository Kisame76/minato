# Classes of framework.jar that may still stand on a stub supertype (ADR-0039 b3.4): such a class compiles against a
# stub and cannot load, so tools/framework-check.sh fails on any other. Each entry names the step that removes it,
# or, since b3.5a, says "stays: <reason>", why the class never loads on Minato's path; the check fails on an entry
# with neither, and on any entry that no longer stands on a stub.
# <class> -> <supertype>  # <the step that removes it> | stays: <why it never loads>
android.content.pm.PackageManager$LegacyPackageDeleteObserver -> android.app.PackageDeleteObserver  # step c: with Binder (decision 10)
android.content.pm.PackageManager$1 -> com.android.internal.pm.parsing.PackageParser2$Callback  # stays: ApplicationPackageManager overrides getPackageArchiveInfo, the only method that makes it, as decision 7 rejects AOSP's parser
android.view.contentcapture.ContentCaptureManager$DataShareAdapterDelegate -> android.view.contentcapture.IDataShareWriteAdapter$Stub  # stays: ContentCaptureManager.shareData makes it, and content capture is off (step c2c1)
android.os.CancellationSignal$Transport -> android.os.ICancellationSignal$Stub  # stays: CancellationSignal.createTransport makes it for a provider's IPC, which no other process calls on Minato (step c2c1)
